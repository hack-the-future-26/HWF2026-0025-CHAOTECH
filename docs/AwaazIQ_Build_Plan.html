2. What AwaazIQ is, and our white space

AwaazIQ takes citizen complaints about rural infrastructure (roads, water, health, schools) in Hindi, Marathi, English or a mix, by text or voice. It removes personal details, places each report on the map, groups related reports, and ranks what needs fixing first using a 9-part priority score built mostly from government records.

The white space (from our research report)

Capability E: prioritising citizen demand against government investment data. Our research report (section 9) found this absent in every system checked, in India and globally. Other systems have multilingual intake, maps, or budget data, but none combines citizen demand with investment data to decide where money should go. The report's matching engine should compare demand and investment on location plus asset type, with three results: funded but not delivered, demanded but not funded, and funded where nobody asked.

The village → specific-asset view we built is the report's feature #21, "Grievance-to-Infrastructure Reclassification" ("which road segment, which health sub-centre catchment"). The report calls it "the deepest structural move in the whole design." It is the unit that Capability E should match against: once each complaint is tied to a specific school, hospital or road, we can ask "was money already sanctioned for this asset?"

5. Ground rules for everyone

  1. Never make up data. If a source can't be fetched, return None and mark the feature "found, not confirmed". This already happened once: a rainfall loader invented numbers with a formula and labelled them as satellite data. It was reverted. Demo complaints are the only sample data allowed, and they must stay flagged is_demo.
  2. Check it live before building on it. A search result is not proof. Mission Antyodaya looked real in search results, but its domain is dead. Pull at least one real row for Kolhapur or Nashik before writing a loader.
  3. Never bypass a CAPTCHA or a login. eMARG and eGramSwaraj are off-limits for scraping for this reason.
  4. Scrape politely: at most about 1 request per second, an honest User-Agent, cache results, and refresh on a schedule (UDISE yearly, JJM monthly, CWC and SACHET every 15–60 minutes).
  5. No complaint is ever auto-rejected. Verification signals only raise or lower confidence and flag reports for an officer. A score may be damped, never zeroed.
  6. The score must stay explainable: the 9 breakdown numbers must add up to the priority score. A test enforces it; don't break it.
  7. Tests before and after every change: python -m intelligence.test_intelligence (79/79), cd backend && python test_citizen_report_endpoint.py (65/65; it writes to the database, so back up backend/hackathon.db first), cd pipeline && python test_pipeline.py (46/46).
  8. After every commit run git status. Only untracked research files may remain. If a tracked file shows as modified after you committed, an editor wrote an old copy back; fix it before moving on.
  9. When you change any frontend file, bump the version tag in index.html/report.html (currently ?v=village5). Otherwise browsers keep the old file and you'll think your change didn't work.
  10. Privacy stays as built: citizen identity lives only in citizen_identity, exact pins are never returned by public endpoints, and pin-based asset coordinates are rounded to 3 decimals (about 110 m).

7. How the priority score works today

Every cluster and every asset gets the same 9-part score (0–100). Four "need" terms are each 0–1 and weighted 25%:

gap points = 81 × confidence_gate × (0.25·demand + 0.25·population + 0.25·infra_deficit + 0.25·vulnerability) priority = gap points + equity (0–10) + strategic (0–4) + urgency (0–3) + feasibility (0–2) − cost penalty (0–3)
TermWhat feeds it nowPlanned change
demandDistinct reporters (by wording), capped at 25Count distinct accounts (C2); soften below 3 reporters (B3)
populationCensus population in the category catchment (road 5 km, water 3, health 8, school 4), log-scaled—
infra_deficitGovernment records (Census 2011, PMGSY, JJM tap coverage, IPHS norms); citizen severity only if no record existsStale-record discount (B1); UDISE+ per-school data (B5); JJM testing (A2)
vulnerabilityCensus: distance to HQ, power hours, drainage, internetStale-record discount (B1)
equityBharatNet fibre down = hard to report from here (+10)—
strategicQualifies under a published scheme rule (+4)—
urgencyFlat +3 for every road and water complaintReplaced by emergency score, cap 15 (B2)
feasibilityNear a block HQ (+2)—
cost penaltyLarger catchments cost more (−3)—
Why a village can rank #1 on one complaint. Halewadi (Kolhapur) scores 68.18 with only 1.62 points from complaints. The rest comes from the government record: 2 doctor posts sanctioned, 0 filled; 46,992 people within 8 km; 84 km from the district HQ; fibre down in all 16 nearby villages. That is the "need, not noise" design working as intended. But the old 3-report minimum was dropped in the asset view, so one complaint (possibly fake) can reach #1. B3 fixes that. And health tends to lead the ranking because its catchment (8 km) is the largest.

A2 · JJM water-testing loader Size: M · Priority: 2 · VERIFIED

9. Workstream B: Scoring engine

Goal: make the score react to current reality, not only 2011 records, while staying explainable and hard to fake. All changes go in intelligence/, constants in config.py, tests in test_intelligence.py.

B1 · Stale-record discount (trust-blend) Size: M · Priority: 1 · decided

Problem it fixes: in the Shinganapur test, 22 people reported a collapsed bridge but the cluster ranked #63 of 114, because Census 2011 says the road is fine and a government record always wins. Now an old record loses weight only when a real burst of recent, severe, independent reports contradicts it.

burst_ratio = (distinct reports in last 72 h / 72) ÷ (all distinct reports / hours since first report) velocity = 0 if burst_ratio ≤ 1, else min(1, ln(1 + burst_ratio) / ln(1 + 20)) freshness = 0.5 ^ (record_age_years / 10) # half-life 10 years (owner decision) contradiction = velocity × share_of_reports_with_high_severity trust = 1 − (1 − freshness) × contradiction infra_deficit = trust × government_value + (1 − trust) × citizen_severity_value
  • Add created_at to _load_reports() in recompute.py; count distinct reporters, not rows (anti-spam).
  • Constants: BURST_WINDOW_HOURS = 72 (already exists), VELOCITY_RATIO_CEILING = 20, RECORD_TRUST_HALF_LIFE_YEARS = 10.
  • Record age: Census = current year − 2011 (compute it, don't hardcode 15); PMGSY = sanction year; UDISE = 2024; JJM testing = current year.
  • Apply to real_infra_deficit and real_vulnerability in all four categories. The burst signal does not go into urgency.
  • Show a third evidence state in the panels: "blended: 48% government record (2011, 15 yrs) + 52% citizen reports".
  • Worked example: Census record 15 years old → freshness 0.354. Shinganapur contradiction ≈ 0.8 → trust ≈ 0.48 → about 10 of the 20 lost infra_deficit points come back.
  • Tests: no burst + old record → record wins; real burst + old record → blend shifts; real burst + fresh record → record still wins; identical copy-pasted reports don't create a burst.

B2 · Emergency urgency Size: L · Priority: 2 · decided

Owner's definition: urgency means an emergency only, meaning bridge or building damage including cracks, graded crack < partial damage < collapse. It is not for potholes, missing staff or water supply (those use demand, infra_deficit and B1). There is no separate emergency list; it lives inside the score.

urgency = URGENCY_MAX × grade × confidence # replaces today's flat +3 grade : crack 1/3 · partial damage 2/3 · collapse 1 (from the damage model or catastrophic wording) confidence : 0–1, built from independent signals (none decisive alone): damage-model score on the photo (C6) · catastrophic wording · burst of reports (B1) · active SACHET alert for the district (A4) · river in flood nearby (A3) · satellite later URGENCY_MAX = 15, GAP_SCORE_MAX_POINTS = 69 (was 3 and 81; total stays 100)

Why 15: tested against the real 116 clusters. A mid-ranked cluster with a confirmed collapse jumps to #8 (partial damage #23), while 9 of the current top 10 stay in the top 10 and clusters move about 4 places on average. A cap of 9 only reaches #28 for a collapse; 20 lets emergencies dominate (#4).

  • Update test_breakdown_sums_to_score and test_score_stays_within_scale for the new caps.
  • Evidence key evidence["emergency"] lists each signal and its contribution, so officers see why.
  • Build the term with every signal optional (missing = 0). It works on wording and bursts first, and gets stronger as A3, A4 and C6 land. No fake inputs.

B3 · Corroboration softening Size: S · Priority: 3 · needs owner decision

The old clusters needed 3 independent reports to be ranked; the asset view needs 1, so a single complaint can reach #1. Recommended option: an asset with fewer than 3 distinct reporters keeps a reduced share of its need points (1 reporter 60%, 2 reporters 80%, 3+ 100%) and shows an "unconfirmed" badge. Implement as an extra factor on the confidence gate in score_cluster so the breakdown still sums. Alternative: fewer than 3 reporters means the asset is not ranked and goes to a separate "unconfirmed" list.

B4 · Fix the demand-vs-investment category bug Size: S · Priority: 1

  • In intelligence/investment.py build_village_investment(), count only reports whose issue_category matches the works' category (PMGSY = road). Today it counts all categories.
  • Return the category in each row, so when school (A1 grants) and water (A5) money arrives the same code handles them.
  • Re-check the headline counts (currently 98 funded-undelivered, 762 demanded-unfunded, 37 funded-not-demanded). They should drop sharply. Remember the demand side is sample data: mismatches are a demonstration, not findings.

B5 · Use UDISE+ in the school score Size: M · Priority: 2 · needs A1

school_deficit = max( major_repair_classrooms / classrooms_total, teacher_shortfall = max(0, 1 − teachers / RTE_required_teachers), no_drinking_water, no_functional_toilet ) # all 0–1
  • For education assets tied to a UDISE school, use this as the asset's real_infra_deficit instead of the village share. Record age = 2024 (fresh).
  • RTE teacher norm: use enrolment from the report card if present; otherwise report the teacher count as evidence only. Don't invent enrolment.
  • Evidence key evidence["school_condition"]: teachers, classroom condition, grant received/spent, year.

B6 · What-if: people reached per rupee Size: M · Priority: 4

Replace "0.4 points per crore" (whatif.py) with the research report's version: given a budget, pick assets in priority order until the money runs out, using real unit costs (the PMGSY median cost per km already computed in realdata.cost_benchmark; school grants from A1), and report the population reached per rupee. 10. Workstream C: Photo checks and fake-complaint defence

Three separate questions, three layers. None of them rejects a complaint; each raises or lowers confidence and flags it.

LayerQuestion it answersHow
1 · CorroborationDid several independent people report it recently?Already built (cap 25, 3-report clusters) plus B1, B3, C2
2 · Photo is genuineIs it a real, new photo taken here, not edited, reused or shown on a screen?C1, C3, C4, C7
3 · Photo shows the problemDoes the photo actually show a pothole, crack or collapse?C5, C6

This mirrors how insurance companies check photo claims: metadata, edit detection, reverse image search, and an AI-image check used only to flag for review. Staffing complaints ("no teacher", "no doctor") can never be photo-verified; only corroboration backs them up.

C1 · Camera-only capture, GPS and time at capture Size: M · Priority: 1

  • In frontend/js/report.js, capture photos with navigator.mediaDevices.getUserMedia + the Image Capture API instead of <input type="file">. capture="camera" is only a hint and still allows gallery uploads on many phones.
  • Take a short burst of 3–5 frames, not one still (used by C7), and read GPS at the same moment (reuse the Task 1 geolocation button).
  • Needs HTTPS (or localhost), same as geolocation.
  • Backend: store capture_lat/lon and captured_at per attachment; flag if the capture point is more than 5 km from the chosen village.

C2 · Count distinct accounts Size: S · Priority: 1

Reports already carry user_id. In recompute.py, count distinct reporters as distinct accounts (fall back to distinct wording only for anonymous/old reports). One person filing the same complaint in different words then counts once.

C3 · Duplicate-photo check Size: S · Priority: 2

Use imagehash (v4.3.1, installs cleanly with Pillow). Store a perceptual hash per attachment; flag any new photo within a small Hamming distance of an existing one from a different village or asset. This catches the same photo reused, even resized or recompressed.

C4 · Edit detection (error-level analysis) Size: S · Priority: 3

Free and local, no API. Re-save the JPEG at a known quality, compare with the original, and flag regions with unusually different error levels (a sign of pasting or retouching). Output a 0–1 "possibly edited" score as evidence for the officer.

C5 · Pothole model as road evidence Size: M · Priority: 2 · team already has the model

  • Run the team's pothole model on road photos in a small service (backend/photo_checks.py). YOLOv8n-size models run on a normal CPU.
  • Output: detections with confidence. Store as evidence["photo_defect"]. It feeds road condition (as extra citizen-severity weight in B1's blend), not urgency.
  • Honest limit: the best published road-damage models reach about 77% F1 (RDD2022 benchmark, which includes Indian roads). Treat the output as a signal, never a verdict.

C6 · Building and bridge damage model (for emergencies) Size: L · Priority: 3

  • Buildings: realistic. A published ground-photo classifier (ResNet50) sorts not damaged / damaged / collapsed at 93.5%. GitHub starting points: najmulmowla1/Earthquake-Building-Damage-Detection (cracked / partially damaged / collapsed). Crack detection (SDNET2018, 56,000 images) reaches 95%+ but only answers "is there a crack", not "is it safe".
  • Bridges: no ready model. Published bridge models detect cracks and corrosion on close-up inspection photos and are weak (mAP50 0.445). A collapse model needs collected, labelled examples.
  • Output the grade (crack / partial / collapse) and confidence for B2.

C7 · Screen-replay check Size: M · Priority: 4 · research needed

Someone could photograph a picture shown on another screen. Photographing a screen leaves moiré patterns (interference between the screen's pixel grid and the camera sensor), screen glare and bezel edges. Research models exist (CNN/Vision Transformer "recapture detection"); KYC companies use the same idea. Cheap first step with C1's burst: a real handheld scene shows small movement between frames; a screen is suspiciously flat. Use it as a signal only.

import re, base64, requests
from Crypto.Cipher import AES              # pip install pycryptodome
from Crypto.Util.Padding import pad
KEY = IV = b"8080808080808080"            # hardcoded in the site's frmValidate.js
def enc(v):
    return base64.b64encode(AES.new(KEY, AES.MODE_CBC, IV).encrypt(pad(str(v).encode(), 16))).decode()

BASE = "https://ejalshakti.gov.in/WQMIS"
s = requests.Session(); s.headers["User-Agent"] = "AwaazIQ/1.0 (+contact)"

import json, requests

def spec(field, op, value):   # operators: eq neq gt gte lt lte in nin btn like null empty member notmember
    return json.dumps({"where": {"expression": {"valueIsRelationField": False,
